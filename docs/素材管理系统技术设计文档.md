# 素材管理系统技术设计文档

## 1. 项目概述

素材管理系统用于统一管理视频制作、AI 动漫、账号运营、数字人等业务中的素材资产。系统管理对象不仅包括素材文件本身，还包括素材元数据、版权信息、标签体系、权限控制、OSS 存储、预览下载、审核流程和操作审计。

系统目标：

- 统一管理视频、音频、图片、3D 模型、数字人、文案等素材。
- 支持素材上传、预览、下载、编辑、审核、归档、禁用。
- 支持按素材类型、大类、安全等级、业务类型、使用场景、标签等多维筛选。
- 支持阿里云 OSS 存储原文件、预览文件、水印文件、缩略图和版权附件。
- 支持内部账号、技术账号、外部账号的差异化权限控制。
- 支持数字人素材和 AI 动漫素材的专属字段管理。
- 所有关键操作必须记录审计日志。

## 2. 技术架构

最终技术栈：

```text
前端：Next.js + TypeScript + Ant Design Pro
后端：NestJS + TypeScript + TypeORM
数据库：MySQL 8
缓存队列：Redis + BullMQ
对象存储：阿里云 OSS
文件处理：FFmpeg + sharp
部署：Docker Compose / 阿里云 ECS + RDS + OSS + Redis
```

总体架构：

```text
Next.js 管理后台
        |
NestJS API 服务
        |
MySQL 8
素材元数据、版权、标签、权限、审计
        |
Redis + BullMQ
缓存、队列、异步任务状态
        |
阿里云 OSS
原文件、预览文件、缩略图、水印文件、版权附件
        |
Worker
截图、转码、水印、图片压缩、版权到期扫描
```

## 5. 数据库设计

数据库使用已有 MySQL 8 表结构，按 Excel 建表为准。

核心表：

```text
素材信息主表
素材来源与版权表
标签字典表
素材标签关联表
账号权限配置表
操作日志审计表
数字人素材信息管理表
AI 动漫素材信息管理表
```

关系设计：

```text
素材信息主表 1 -- N 素材来源与版权表
素材信息主表 N -- N 标签字典表，通过素材标签关联表
素材信息主表 1 -- N 操作日志审计表
素材信息主表 1 -- 0/1 数字人素材信息管理表
素材信息主表 1 -- 0/1 AI 动漫素材信息管理表
账号权限配置表控制动作权限和数据权限
```

服务层规范：

- `是/否` 字段在代码中映射为 boolean。
- 状态字段在代码中映射为 enum。
- 多选逗号字段先保留，统一封装解析逻辑。
- 文件大小建议后续增加字节数字段。
- 操作日志只允许追加，不允许业务侧修改或删除。
- 即使数据库没有外键，也要在服务层校验关联数据存在性。

## 6. OSS 存储设计

使用阿里云 OSS，Bucket 设置为私有读写。

目录设计：

```text
assets/original/{yyyy}/{mm}/{assetId}/{filename}
assets/preview/{yyyy}/{mm}/{assetId}/{filename}
assets/thumbnail/{yyyy}/{mm}/{assetId}/{filename}
assets/watermark/{yyyy}/{mm}/{assetId}/{filename}
copyright/files/{yyyy}/{mm}/{assetId}/{filename}
temp/uploads/{userId}/{uploadId}/{filename}
```

数据库中保存 OSS 元数据：

```text
bucket_name
object_key
original_file_name
file_size
mime_type
etag
storage_class
preview_object_key
thumbnail_object_key
watermark_object_key
copyright_file_object_key
```

访问规则：

- 前端不直接拼接 OSS 地址。
- 所有 OSS 访问都由后端生成短期签名 URL。
- 原文件下载必须校验下载权限。
- 外部账号只返回水印预览地址。
- 版权文件必须校验版权查看权限。
- 数字人模型必须校验数字人模型查看权限。
- 机密素材禁止外部账号访问。

## 7. 权限设计

权限模型采用：

```text
RBAC 动作权限 + ABAC 数据权限
```

RBAC 控制用户能做什么：

```text
查看素材
查看数字人模型
查看版权文件
上传素材
编辑素材
删除素材
拆分素材
打标签
下载原文件
导出数据
审核权限
```

ABAC 控制用户能访问哪些数据：

```text
账号类型
角色名称
素材安全等级
素材大类
素材状态
外部可预览
外部可下载
版权文件是否外部可见
```

核心权限方法：

```ts
canViewAsset(user, asset)
canPreviewAsset(user, asset)
canDownloadOriginal(user, asset)
canViewCopyright(user, asset)
canViewDigitalHumanModel(user, asset)
canEditAsset(user, asset)
canDeleteAsset(user, asset)
canReviewAsset(user, asset)
```

三类账号策略：

```text
内部账号：
可查看普通、内部素材；可上传、编辑、打标签、拆分、预览；
可下载非机密素材；不可删除、不可审核、不可查看版权机密。

技术账号：
可维护存储、加密、备份、路径；
可查看素材基础信息；
不可下载原文件，不可查看数字人模型和版权文件。

外部账号：
仅可预览授权的普通素材；
强制水印；
不可下载、编辑、删除、拆分；
不可查看数字人模型、版权文件、存储路径。
```

## 8. 核心业务流程

素材上传流程：

```text
1. 前端选择文件
2. 后端创建上传任务
3. 后端返回 OSS 上传参数
4. 前端直传 OSS
5. 前端通知后端上传完成
6. 后端校验 OSS 文件存在
7. 写入素材主表
8. 写入版权信息、标签关联、扩展信息
9. 素材状态设为待审核
10. 投递异步任务生成缩略图、预览、水印
11. 写入操作日志
```

素材预览流程：

```text
1. 用户请求预览
2. 后端校验登录态
3. 校验查看素材权限
4. 校验安全等级和素材大类
5. 判断是否需要返回水印预览
6. 生成 OSS 短期签名 URL
7. 写入查看日志
```

素材下载流程：

```text
1. 用户请求下载
2. 校验下载原文件权限
3. 校验素材安全等级
4. 校验外部可下载策略
5. 生成原文件短期签名 URL
6. 写入下载日志
```

审核流程：

```text
1. 审核员查看待审核素材
2. 校验素材基础信息、版权信息、安全等级
3. 审核通过后状态改为正常
4. 审核驳回后记录驳回原因
5. 写入审核日志
```

版权到期流程：

```text
1. 定时任务每日扫描授权结束时间
2. 到期前 30 天标记即将到期
3. 已过期素材标记版权异常
4. 可选：自动禁止外部预览和下载
5. 写入系统日志
```

## 15. 最终结论

本项目建议采用全 TypeScript 技术栈：

```text
Next.js + Ant Design Pro
NestJS + TypeORM
MySQL 8
Redis + BullMQ
阿里云 OSS
FFmpeg + sharp
```

第一版不要做微服务，采用模块化单体后端即可。系统核心要先打通“素材入库、OSS 存储、权限校验、预览下载、版权管理、审计日志”这条主链路。等素材处理量、搜索复杂度、外部访问规模上来后，再把 Worker、搜索服务、预览服务独立拆分。
